    Question 1

    Is this identification real?

    Fragment traces, isotope envelope, measured-versus-library spectrum. Every tool in the field answers this one.

    DIA-NN · Skyline · Spectronaut → solved
    Question 2

    Why is my peptide missing?

    No engine pre-extracts chromatograms for candidates it rejected, so the evidence behind a negative result does not exist on disk. Random access means we build it on the spot.

    everyone else → cannot be asked
    Question 3

    What else is in this window?

    The neighbourhood map slices raw m/z × RT around the match. Interference stops being a score in a column and becomes something you look at.

    everyone else → weakly served
    Delivery phases
    Phase 1 · now
    The workbench

    Sets up, runs and inspects DIA-NN — no OpenDIAlyzer engine needed. mzPeak drilldown, Interrogate, and one range-read abstraction that is local today and HTTP later.

    Phase 2
    Provenance

    Every processing step recorded as a signed graph: parameters, input hashes, versions, timings. Methods text and a machine-readable record fall out of it.

    Phase 3
    SDRF & ISA

    Experiment design as a first-class editable grain, not an import. ISA investigation/study/assay above it; annotation and curation state alongside.

    Phase 4
    Repository submission

    One action assembles a complete, validated ProteomeXchange / PRIDE submission from what is already tracked.

    Phase 5
    Cluster & cloud

    The engine moves to a CUDA cluster; the GUI stays a client because it was always reading byte ranges. Object-store datasets, same code path.
